# Повторить заказ — дизайн

Дата: 2026-11-25 · Размер: небольшая доработка, два PR

## Зачем

Покупатель хочет быстро купить то же самое снова. Кнопка «Повторить заказ» кладёт товары прошлого заказа в корзину, чтобы не искать их заново.

## Цели

- Одно нажатие: доступные товары заказа оказываются в корзине с тем же размером и количеством, по текущей цене. Покупатель попадает в корзину.
- Честно сказать, чего не удалось добавить и почему.

## Не цели

- Переход сразу на оформление: покупатель сначала видит корзину.
- Повтор заказа, который ещё в работе (`placed`, `assembling`, `in_delivery`).
- Замена недоступного товара похожим.

## Анти-цели

- В корзину попадает удалённый, закончившийся или «Direct-only» товар, и ошибка всплывает только на «Оформить».
- Тихая потеря: покупатель не узнаёт, что часть заказа не добавилась.
- Корзина покупателя очищается или перезаписывается: товары заказа **добавляются** к её содержимому.

## Подходы

| | Суть | Плюсы | Минусы |
|---|---|---|---|
| **А (выбран)** | Запросить каждый товар заново, доступные положить в корзину, открыть корзину | Только то, что можно купить, по актуальной цене; покупатель видит итог до оформления | Запрос на каждый товар, кнопка недолго показывает «Добавляем…» |
| Б | То же, но сразу на оформление | На одно нажатие быстрее | Изменения видны только в форме заказа, количество там не поправить |
| В | Без запросов, товары из данных заказа | Мгновенно | В корзину попадает недоступное по старой цене, ошибка только на «Оформить» |

Выбран А: пользователь хочет быстро купить то же самое снова, без неожиданностей при оформлении.

## Решения

**Логика** — сервис `RepeatOrderService` в `src/app/core/`, метод `repeat(order: Order): Observable<RepeatResult>`.
- Для каждого уникального `product_id` из `order.lines` параллельно вызывает `api.product(id)`. Ошибка одного запроса не роняет остальные: такой товар считается недоступным.
- Позиция **недоступна**, если: товар не пришёл (404 или другая ошибка), `!in_stock`, `directOnly(product)` (лавка теперь принимает заказы только в Direct), `price === null`, или размер позиции больше не входит в `product.sizes` (если у товара есть размеры).
- Доступные позиции идут в `cart.add(product, line.size, line.qty)` в порядке заказа. `false` от `add` (лимит 30 позиций) означает «не поместилось». Количество режет сам `add` до 20.
- `RepeatResult`: `{ added: number; total: number; unavailable: string[]; overflow: number }`. В `unavailable` — названия товаров.

**Сообщение и переход.**
- Добавлено всё: тост «Добавили в корзину N товаров» (с правильной формой слова) и переход на `/cart`.
- Добавлено не всё: тост «Добавили X из Y. Нет в наличии: «название», «название»» (до двух названий, дальше «и ещё K»). Если что-то не влезло по лимиту: «Корзина заполнена — не поместилось K». Переход на `/cart`.
- Не добавлено ничего: тост-ошибка «Товаров из этого заказа сейчас нет в наличии», остаёмся на странице.
- Все запросы упали из-за сети (ни один товар не пришёл и ни одного 404): тост-ошибка «Не удалось повторить заказ. Проверьте интернет и попробуйте ещё раз».

**PR 1 — страница заказа.** Кнопка «Повторить заказ» в блоке действий (`#actions`, рядом с «Продолжить покупки»), только для `stage` `delivered` и `cancelled`. Пока идут запросы: `disabled` и текст «Добавляем…». Повторное нажатие во время запросов игнорируется.

**PR 2 — «Мои заказы».** Та же кнопка у доставленных и отменённых заказов в списке. Сейчас строка целиком является ссылкой, поэтому вёрстку строки нужно перестроить: ссылка остаётся на содержимом, кнопка стоит рядом, вне ссылки. Логика — тот же `RepeatOrderService`. Ветка PR 2 делается поверх PR 1.

## Оставлено исполнителю

- Точное место кнопки в блоке действий и её вид (`btn` или `btn--ghost`) — по тому, что на странице заказа главное действие.
- Формы слова «товар» — через существующий `plural`.
- Тесты: спека сервиса (все доступны; 404, нет в наличии, Direct, исчезнувший размер; лимит корзины; сетевой сбой; один `product_id` в двух позициях с разными размерами запрашивается один раз) и спека страницы заказа (кнопка только у `delivered`/`cancelled`, «Добавляем…», тосты, переход в корзину).
